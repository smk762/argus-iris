Add a GPU service

  1. Give the service its broker URL and token. With argus-cortex 0.15 that is all: the client finds gpu-tenant.yaml, registers it at startup and renews it.
  1. List what it keeps loaded in its manifest. iris finds the container on whichever node runs it and uses that node's address with the container's published port (port picks one when it publishes several). An admin_auth resident gets the service's own ARGUS_ADMIN_TOKEN.
tenant: my-service
residents:
  - name: my-model
    adapter: argus-http
    container: my-service-engine
    port: 8000
    vram_mb: 4000
    unload_path: /admin/unload
    warm_path: /admin/wake
    admin_auth: true
  1. Optional: let iris start and restart it. Label the container in its own compose file (labels: {argus.iris.manage: "true"}) on a host whose agent sets IRIS_AGENT_MANAGE_LABEL=1. Without it, iris still reads, evicts and warms it over HTTP.

Removing it: stop the service. It signs off on shutdown; iris keeps it while its container exists (so a warm can start it) and drops it once the container is removed, or at once with Forget.

Add a GPU host

Run iris-agent there with the agent token and this broker's URL. It announces itself and shows up as a node within a minute.

Set IRIS_AGENT_URL only when the broker cannot reach the agent at the address its announcement comes from.

Broker token

Manual actions (warm, evict, forget) send ARGUS_GPU_BROKER_TOKEN as a bearer token. It is kept in this tab's session storage only.
